Dispatch hands a task to a new pi session in the board terminal:

1. The parent session calls `dispatch_start` with a self-contained task, and optionally a folder, name, model, thinking level, and group.
2. The worker runs on its own. When it is done, it calls `dispatch_report` once.
3. The parent calls `dispatch_wait` to get the report. `dispatch_list` lists the workers, and `dispatch_end` ends one.

The parent never talks to the worker. The board starts the worker and holds its report, so the parent gets the report even when the worker's terminal has ended or the board restarted. The sidebar marks a dispatched session with its own icon.

Dispatch needs the board terminal. From a shell, `pi-kanban dispatch start | wait | list | end` does the same. See the [CLI reference](../../reference/cli/#dispatch).
