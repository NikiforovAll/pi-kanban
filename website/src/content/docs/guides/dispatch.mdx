Dispatch hands a task to a new pi session in the board terminal:

1. The parent session runs `pi-kanban dispatch start` with a self-contained task. The command prints the worker's session id. [Options](../../reference/cli/#dispatch-start) set the folder, name, model, thinking level, and group.
2. The worker runs on its own. When it is done, it calls the `dispatch_report` tool once.
3. The parent runs `pi-kanban dispatch wait <id>` to get the report. `dispatch list` shows the workers, and `dispatch end` ends one.

The parent never talks to the worker. The board starts the worker and holds its report, so the parent gets the report even when the worker's terminal has ended or the board restarted. The sidebar marks a dispatched session with its own icon.

Dispatch needs the board terminal. The `dispatch` skill teaches pi these commands. They also run from a shell. See the [CLI reference](../../reference/cli/#dispatch).
